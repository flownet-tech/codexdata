# Hook registry failure modes

- Broad path or product-name matching misattributes unrelated scripts; require distinctive literal path suffixes, complete filename boundaries, and negative examples.
- A copied/renamed command is treated as verified ownership or safety; describe matches as path evidence only, retain unknown/ambiguous results, never auto-select removal.
- Community data introduces executable expressions, unsafe links, personal paths, or incomplete translations; validate a closed schema, HTTPS references, redacted examples, and required en/zh copy before building.
- Producer artifacts drift from reviewed source; deterministic build and CI check generated files.
- Client network failure delays scanning/deletion or hides commands; load descriptions separately with bounded requests, caching/backoff, and explicit unavailable state.
- New schema or malformed entry breaks the client; reject incompatible data and retain last valid cache.
- Matching sends commands to the service; download the full public registry and match on-device only.
